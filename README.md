# Тестовое Neowise. AI-помощник для входящих заявок

Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

## Запуск

В репозитории есть сервер, HTML-страница и имитатор модели. Нужен Node.js 20 или новее. Зависимостей и ключей нет.

```sh
node server.mjs
```

Сервер напишет адрес в консоль. Откройте http://127.0.0.1:3000. Порт можно задать через переменную `PORT`.

## Тесты

Из корня проекта выполните:

```sh
node --test
```

Тесты сами запускают HTTP-сервер на свободном порту и закрывают его после проверок.

## Работа с заявкой

Введите учебную заявку, например «Какова стоимость доставки?». Проверьте предложенную тему и черновик перед отправкой клиенту. При сообщении «Разберите заявку вручную» исходный текст остаётся в форме.

## API

`POST /api/triage` принимает JSON `{"text":"…"}` с непустой строкой.

| Ситуация | Ответ |
|---|---|
| Битый JSON, не объект, отсутствующий, нестроковый или пустой `text` | HTTP 400, `{"status":"invalid_input"}` |
| Тело больше 64 КБ | HTTP 413, `{"status":"payload_too_large"}` |
| Модель вернула тему `delivery`, `pricing` или `other` и непустой черновик | HTTP 200, `{"status":"ready","topic":"…","draft":"…"}` |
| Модель не ответила за 300 мс, упала или вернула неподходящий ответ | HTTP 200, `{"status":"manual_review","topic":null,"draft":null}` |

Результат модели проверяется в `classifyRequest` в `server.mjs`. Ответ клиенту собирается только из проверенных полей.

Для локальной проверки имитатор принимает любой обычный текст. Метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` включают отдельные сценарии сбоя.
